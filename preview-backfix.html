返回键在标签页之间倒着走 —— 修复

githup 1.1.3 · 现象：首页 → 通知 → 探索，按返回会逐个标签退回去
修复前
探索→按返回→ 通知→按返回→ 首页→按返回→ 退出应用
按了 3 次才退出。底部标签被当成了一层层可以退回的历史。
修复后
探索→按返回→ 退出应用
任何标签页按返回即「没有上一层」，交给「再按一次退出」。

根因：两处设计互相矛盾

第一处，pushRoute() 里横向切标签故意不加深：

var isLateral = Router.isRoot(path) && Router.isRoot(location.hash || '#/');
if (!isLateral) routeDepth++;      // 横向切标签，深度不变

第二处，canGoBack() 又有一条兜底，反过来认定「横向也有一层可退」：

if (routeDepth > 0) return true;
var now = (location.hash || '#/').replace(/^#/, '').split('?')[0];
return now !== '' && now !== '/' && this.isRoot(now);   // ← 停在标签页就返回 true

深度虽然不涨，但 canGoBack() 始终为真 —— 返回键就沿着 history 里那些标签条目一条条往回走。

改了什么

位置改法
canGoBack()简化为 return routeDepth > 0;，只看纵向深度
pushRoute()横向切标签改用 replaceState，不再往历史里堆条目
TAB_ROOTS补上首页 '/' —— 原来漏了，导致「首页↔其他标签」被误判成纵向深入
横向判据收紧成「当前位置也是标签页」，保住「详情页点标签栏」这条纵向回退
最后一条是关键边界：若只判断目标位置，从仓库详情点底部标签栏时 replaceState 会覆盖掉详情页那条历史，用户再按返回就直接退出应用了。Router.go 里本来就有注释警告过这个坑。

验证（用真实 app.js 在沙箱里跑）

场景期望结果
首页 → 通知 → 探索，按返回直接栈底退出✅ 历史仅 1 条
首页→我的→搜索→通知→探索 乱序切同上✅
探索 → 仓库详情 → 议题，逐级返回议题→详情→探索✅ 纵向层级不变
首页 → 详情 → 返回回到首页且不再可退✅
详情页 → 点标签栏 → 返回回到详情页✅
横切多标签 → 进详情 → 返回回到进详情前停留的标签✅
测试不是重写一份逻辑来「自证」，而是从 app.js 里抠出 TAB_ROOTS / pushRoute / Router 三段真实源码放进沙箱执行。
