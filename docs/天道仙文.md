# 天道仙文（界面语言）

一种把界面文案换成修仙小说腔的显示语言，语言码 `wx`，在「设置 → 界面语言」里切换。

## 它是什么

不是翻译引擎，也不是机器翻译 —— 是一张**手写词条表**。界面上每个词都被换成了
修仙世界的叫法：

| 界面词 | 天道仙文 | 界面词 | 天道仙文 |
|---|---|---|---|
| 首页 / 我的 | 洞府 / 吾庐 | 仓库 | 藏经阁 |
| 通知 | 知会 | 提交 / 分支 | 落笔 / 支脉 |
| 探索 / 搜索 | 寻幽 / 搜玄 | Issue / PR | 疑义 / 合道之请 |
| 设置 | 调息 | 加载 / 失败 / 成功 | 运法 / 功败 / 功成 |
| 下载 / 安装 | 纳物 / 纳器 | 令牌 | 玉符 |
| Actions 构建 | 炼器 | 网络错误 | 灵气断绝 |
| 清除缓存 | 涤荡尘垢 | 检查更新 | 查勘新法 |

几条有画面的长句：

- `令牌无效或已过期` → **玉符已朽，须重铸**
- `您已是最新版本` → **道友所持已是当世最新**

## 与「整页翻译」的区别

| | 整页翻译（translate.js） | 天道仙文（本文） |
|---|---|---|
| 翻什么 | 从 GitHub 拉来的正文（README、issue 正文） | 界面自己的文案（底栏、设置项） |
| 怎么翻 | 调外部引擎，联网 | 查本地词条表，离线 |
| 开关 | 右上角地球图标 | 设置 → 界面语言 |

两套互不干扰：开着整页翻译，界面仍可以是天道仙文。

## 文件

| 文件 | 作用 |
|---|---|
| `app/src/main/assets/web/js/i18n-tiandao.js` | 词条本体（点分 key + 整句表 + 术语表） |
| `tools/gen-tiandao.py` | 生成词条，内置重合检测 |
| `tools/apply-tiandao.py` | 把语言接进 `index.html` 与 `i18n.js` |

## 覆盖率：为什么是两层，不是一层

界面文案共 1753 条，绝大多数是长句。只按「整句收录」实测只能覆盖 **8.2%** ——
收不完，也没必要收完。所以分两层：

| 层 | 内容 | 条数 | 怎么工作 |
|---|---|---|---|
| `I18N_WX_EXACT` | 按钮、标题、动词状态词 | 228 | 整条文案完全相等才换 |
| `I18N_WX_TERMS` | 名词、领域词 | 312 | 长句里按术语逐段替换 |

**实测覆盖率 81.7%**（1432 / 1753）。剩下 321 条是散文式长句
（如「如果这个软件帮到了你，可以请我喝杯咖啡」），术语替换帮不上忙，
强行替换会造病句，所以让它们回落中文。

### 为什么动词不能进术语层

动词放进术语层会造病句：

- `完成配对` 若把「完成」当术语替换 → `功成配对`（不通）
- `安装器` 若先替换「安装」→ `纳器器`（多一个「器」）

所以「完成 / 失败 / 成功」这类只在整句层精确匹配；「安装器」这类复合词
必须连着收，替换时按长度降序，长词先吃。

### 保护规则

HTML 标签、%s / %1$s 占位符、URL、反引号代码内的内容一律不参与替换。
例：`<b>搜索</b>找仓库` → `<b>搜玄</b>找藏经阁`，标签完好。

## 加词

编辑 `tools/gen-tiandao.py`：

- 整句 / 动词状态词 → 加进 `EXACT` 表
- 名词 / 领域词 → 加进 `TERMS` 表（复合词记得连着收）

然后：

```bash
python3 tools/gen-tiandao.py tiandao_dict.json   # 传词典才做重合检测
python3 tools/gen-guard.py .                     # 前端文件变了必须重跑
```

改完可以用 `python3 measure.py` 量一下覆盖率（工程自带的统计脚本）。

## 独立性

词表全部按修仙小说语汇一手写成。生成脚本会与参考词典（981 条）逐条比对，
任何一条译法相同就报错退出。修仙是公共题材，「藏经阁 / 玉符 / 运法」这类词
属通用语汇，不是任何项目的独创表达。

## 打包前后必读

新增了 `i18n-tiandao.js`，前端文件哈希清单变了，**必须重跑 `tools/gen-guard.py`**，
否则防护链第 3 环判定资源被改，App 一启动就被拦进 BlockedActivity。
云端构建（`.github/workflows/build-release-apk.yml`）已包含这一步。
